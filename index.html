Playwright for desktop apps.

An AI explores your app once through the operating system's accessibility tree. BAM replays it as a test suite forever: no model, no tokens, an HTML report with proof screenshots. macOS, Windows, Linux, and the Steam Deck.

01Explore once. Replay forever.

Most computer-use tools send a screenshot to a vision model on every step. bad-ass-mcp reads the same tree screen readers use, so the expensive part only has to happen once.

EXPLORE

An AI drives the real app

Claude, Codex, Gemini or a local model uses the MCP tools to find buttons by role and name, click, type, drag and check results.

Costs tokens. Once.

SCRIPT

The path becomes a BAM script

Plain JSON: learn elements by name, run steps, check what happened. Per-platform values, setup commands, retries, readable diffs.

Lives in your repo.

REPLAY

bad-ass-mcp run smoke/

No model in the loop. Every script runs against the real app and writes a results folder with screenshots per phase and an HTML report.

Free. Every time.

02A script is just JSON

This one checks a Markdown editor's emoji picker: open it, search, press Enter, save. The same file runs on Windows and Linux.

// smoke/emoji-picker.json (trimmed)
{
  "name": "emoji-picker",
  "platforms": ["windows", "linux"],
  "launch": ["emoji.md"],
  "phases": [
    {
      "learn": { "emoji": { "name": "Insert emoji" } },
      "steps": [
        { "action": "click", "target": "emoji" },
        { "action": "wait_for_element", "name": "Search emoji" }
      ]
    },
    {
      "learn": { "search": { "name": "Search emoji" } },
      "steps": [
        { "action": "type", "target": "search", "text": "crab" },
        { "action": "key", "key": "Return" }
      ]
    }
  ]
}

04One API, every desktop

The same tools and the same scripts on all three operating systems, through each one's native accessibility API.

AXUIElement

macOS

Native Cocoa apps, WKWebView (Tauri) and Electron.

UI Automation

Windows

Win32 and WebView2 apps, including large native game-modding editors.

AT-SPI2

Linux

GTK, Qt and WebKitGTK apps on X11. Tested on KDE Plasma and Xfce.

AT-SPI2 + XTEST

Steam Deck

Desktop Mode and Gaming Mode (gamescope). Yes, really.

05Why the accessibility tree

Every major OS already describes every button, field and menu in every app, for screen readers. bad-ass-mcp speaks that language directly.

Fast and cheap

A tree read is structured text, not a screenshot round trip through a vision model.

Works in the background

Clicks and value changes fire on the control objects themselves, so the target window doesn't need focus for most actions.

Names, not pixels

Scripts target "Insert emoji", not (812, 44). A theme change or a resized window doesn't break them.

Vision as a last resort

Canvas, GL and games have no tree. screenshot, click_at and drag cover those, like the wiring above.

06Install

Python 3.11+. Optional: ffmpeg and gifsicle for screen recording.

pip install 'bad-ass-mcp[macos]'
# then grant Accessibility to your terminal in System Settings → Privacy & Security
claude mcp add bad-ass-mcp --scope user -- bad-ass-mcp
pip install "bad-ass-mcp[windows]"
claude mcp add bad-ass-mcp --scope user -- bad-ass-mcp
# Debian/Ubuntu: PyGObject and AT-SPI come from the distro
sudo apt install python3-gi gir1.2-atspi-2.0 at-spi2-core xdotool x11-utils imagemagick
python -m venv --system-site-packages venv && . venv/bin/activate
pip install bad-ass-mcp
claude mcp add bad-ass-mcp --scope user -- bad-ass-mcp

Works with any MCP client: Claude Code, Claude Desktop, Codex, Gemini CLI, or a local model through an OpenAI-compatible bridge. Full docs on GitHub, the script format in docs/bam.md.
